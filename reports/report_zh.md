## 摘要

本项目在课程提供的 WikiText-2 与固定 BPE-2048 协议上，从随机初始化训练小型自回归语言模型，研究前馈网络门控、正则化与模型容量对预测质量的影响。在相同的 9,830,400 个训练目标和随机种子 17 下，以参数量接近的 SwiGLU 替换 GELU 前馈网络，将验证集 bits per byte（BPB）从 2.07109 降至 2.00788；单独加入 0.05 或 0.10 dropout 未改善基线。在 SwiGLU 与 0.05 dropout 的组合上，增加训练预算后，128 宽度模型达到 1.73074 验证 BPB；在相同 6000 步训练预算下增宽至 192，达到 1.66915。该结果不能全部归因于单一机制，也不等同于测试成绩。已有完整测试记录中，128 宽度、2400 步组合模型的测试 BPB 为 1.86283。全部主要结论来自单次随机种子实验，未建立统计显著性。

## 1. 任务与基线

任务是在保持数据、分词器和评估器不变的前提下，降低完整测试集 BPB。协议为 `7506-mp1-wt2-v2`，词表为 2048，评估使用独立的 256-target 因果窗口，不在窗口间携带临时状态。每个 split 除首 token 外的目标都被计分，包含最后不足一个窗口的部分。定义为：

`BPB = Σ[-ln p(x[t+1] | x[≤t])] / (ln(2) × split 原始 UTF-8 字节数)`。

验证集含 376,599 个评分目标、1,148,007 字节；测试集含 428,405 个评分目标、1,292,013 字节。验证用于开发与选择，测试用于固定模型的最终评估。WikiText-2 的来源见课程数据说明；本地当前数据与 tokenizer 的四项哈希校验均通过。

基线使用 4 层、4 注意力头、宽度 128 的 GPT，包含学习式绝对位置编码、Pre-LayerNorm、因果注意力、残差连接和输入输出词嵌入权重共享，共 1,088,256 个参数。实验保留了这些机制，仅对前馈网络、dropout 和宽度进行指定改变。

## 2. 方法与研究假设

### 2.1 参数量接近的 SwiGLU

基线前馈网络为 `Linear(d,4d) → GELU → Linear(4d,d)`。SwiGLU 使用三个线性映射：

`FFN(x) = down(SiLU(gate(x)) ⊙ value(x))`。

其中 ⊙ 表示逐元素相乘，三个映射均包含偏置。门控分支根据输入调节内容分支。这一结构参考 Shazeer 的 GLU 变体研究 [1]；本项目是对已有方法的实现与检验，不声称提出新结构。研究假设是在相近参数预算下，门控可以改善特征转换。

为避免将增加参数量误判为门控收益，中间宽度取 `round(8d/3)`：d=128 时为 341，d=192 时为 512。128 宽度的基线与 SwiGLU 分别有 1,088,256 和 1,088,424 个参数，只差 168 个。新的线性层沿用基线的正态初始化（标准差 0.02，偏置为零）。

### 2.2 前馈输出 Dropout

Dropout 置于前馈输出之后、残差相加之前，即 `x + Dropout(FFN(LayerNorm(x)))`，评估时关闭。其动机是减少训练过程中特征间的过度依赖 [2]。基线分别试验 p=0.10 和 p=0.05；后续组合使用 p=0.05。基线上的结果没有证明这种正则化有效，组合中的独立收益也尚未被隔离。

### 2.3 容量与训练预算

在保持深度和头数不变时，将宽度从 128 提高到 192，参数量增至 2,223,232。规模研究 [3] 为考察容量提供背景，但不预测本任务的具体收益，192 也不是文献给出的最优值。训练预算比较使用 2400 和 6000 步。由于余弦学习率依赖总步数，改变预算同时改变了学习率轨迹，结果不能解释为单纯在同一 checkpoint 后继续训练的收益。

## 3. 实验设置与来源

所有已记录正式实验使用 seed=17、batch size=32、256 个目标/序列、4 CPU threads、FP32 和 PyTorch 2.7.1。优化器为 AdamW，最大学习率 0.001、weight decay 0.1，前 100 步线性预热，之后使用脚本中的余弦因子，最低因子为最大值的约 0.1；梯度裁剪阈值为 1.0。窗口从训练 token 序列随机采样，可重复覆盖文本。

`train_tokens = steps × 32 × 256`，指处理过的训练目标次数，不是互不重复的 token 数。训练脚本没有恢复 checkpoint 的路径，各次运行从随机初始化开始。报告制作时环境为 macOS 27.0 / arm64、Python 3.12.9；历史日志只标注 CPU，未记录具体芯片型号，不能将当前环境信息等同于完整历史硬件证明。

证据来自 `code/runs/*/metrics.json` 和对应评估 JSON；完整摘录、训练曲线和 checkpoint 哈希保存在 `experiment_evidence.json`。草稿制作时仓库 HEAD 为 `1235d3acae75bf19ada33b701446ea4a399a037d`，不是各训练运行均使用这一 commit 的证明，也不是尚未确定的最终提交 commit。

## 4. 结果与消融

| 方法 | 宽度 | 步数 | 参数量 | 验证 BPB | 训练秒数 |

| 基线 GELU | 128 | 1200 | 1,088,256 | 2.07109 | 209.56 |
| GELU + dropout 0.10 | 128 | 1200 | 1,088,256 | 2.08875 | 218.09 |
| GELU + dropout 0.05 | 128 | 1200 | 1,088,256 | 2.08191 | 232.16 |
| SwiGLU | 128 | 1200 | 1,088,424 | 2.00788 | 187.87 |
| SwiGLU + dropout | 128 | 2400 | 1,088,424 | 1.83138 | 474.00 |

| SwiGLU + dropout | 192 | 6000 | 2,223,232 | 1.66915 | 1644.08 |


表中训练耗时使用 `train_seconds`，不含脚本记录的中间验证时间，不是 CPU 评分耗时。完整 run ID 映射和精确值见 `experiment_tables.md`。

### 4.1 相同训练量的机制比较

在 1200 步下，纯 SwiGLU 相比基线降低验证 BPB 0.06320（约 3.05%）。两者处理相同数量目标，结构参数量接近，可作为前馈机制的对照及消融：移除 SwiGLU、恢复 GELU 后，成绩回到基线结果。虽然随机种子相同，替换模块会消耗不同数量的随机数，因此不是逐权重完全匹配的实验；尚需多种子运行检验稳定性。

Dropout 0.10 和 0.05 分别将基线验证 BPB 提高约 0.01766 和 0.01082。在当前 1200 步设置下没有观察到收益。可能解释是额外正则化妨碍有限预算下的拟合，但现有实验不足以确定原因。

### 4.2 训练预算与容量比较

128 宽度组合从 2400 到 6000 步，验证 BPB 由 1.83138 降至 1.73074，降低约 0.10064。6000 步曲线从 2000 步的 1.84721，经过 4000 步的 1.75890、5000 步的 1.74111，下降到最终 1.73074，后期收益缩小，没有已记录的验证反弹。

在相同 49,152,000 个训练目标下，宽度 192 比宽度 128 降低 BPB 0.06158（约 3.56%），记录的训练时间由 1255.36 秒增至 1644.08 秒（约增加 31.0%），参数量约增加 104.3%。这是容量增加与成本的取舍，不是 SwiGLU 单独带来的收益，也不是相同计算预算比较。

最佳验证结果 1.66915 比初始基线低约 19.41%，但二者同时在结构、正则化、训练量和容量上不同，不能将这个总差额归因于单一因素。

## 5. 成本、资源与复现

7 次正式训练与 1 次 10 步流程检查合计处理 157,368,320 个训练目标，累计训练 4222.98 秒（70.38 分钟），训练进程累计 4502.94 秒（75.05 分钟）。该成本仅覆盖仍有日志的运行，不含独立评分、失败或删除的运行、安装及人工开发时间。

宽度 192 checkpoint 为 8,913,653 字节（8.50 MiB），低于 64 MiB，但这不是完整未压缩推理包的核算。较早 2400 步模型的记录评分时间约为基线的 0.963 倍，属于单次历史测量；不能证明宽度 192 模型的评分时间。CPU 峰值内存未测量；日志中的 CUDA 内存字段在 CPU 上为零，不代表 CPU RAM 为零。因此尚不能宣称最佳验证候选满足全部资源限制。

复现环境按课程 README 安装 Python 3.12、PyTorch 2.7.1 和 requirements。所有命令从 `code/` 运行，并使用新的输出目录：

## 6. 局限与结论

结果支持在这一单种子、小规模实验中采用近等参数 SwiGLU，并表明更大训练预算和宽度带来额外验证收益。单独 dropout 的收益没有得到支持。缺少 6000 步、同宽度 GELU 对照，以及同预算的纯 SwiGLU 对照，因而不能分离最终组合中每个机制的贡献。一次计时不能证明稳定加速；同种子结果也不构成统计显著性证据。

最终提交前仍需填写姓名学号、明确冻结的提交 checkpoint、补齐该版本的评估与资源证据、提供不可变代码和模型链接，并将报告导出到不超过 10 页。宽度 192 是当前验证最优候选，不自动等同于最终已提交模型。

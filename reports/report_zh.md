## 摘要

本项目在课程提供的 GPT 基线上，从随机初始化训练语言模型，逐步考察 dropout、SwiGLU、训练预算、宽度、深度以及旋转位置编码。初始基线验证 BPB 为 2.07109。在相同 1200 步训练预算下，近等参数 SwiGLU 将验证 BPB 降至 2.00788，但在宽度 192、6 层和 6000 步设置下，GELU + dropout 的 1.60688 优于 SwiGLU + dropout 的 1.63767，说明收益依赖实验设置。进一步采用宽度 256 的 RoPE、GELU 和多处 dropout 组合，得到 CPU FP32 验证 BPB 1.52770、完整测试 BPB 1.54400。该组合同时改变多项因素，不能把全部提升归因于 RoPE。本文报告有效和无效改动、消融对照及资源检查，并明确单种子与测试时间顺序的局限。

## 1. 任务、数据与基线

使用固定协议 `7506-mp1-wt2-v2`、课程 WikiText-2 数据和 BPE-2048 分词器。模型根据已观察前缀预测下一 token，评估窗口固定为 256 个目标，窗口之间不保留文本状态。验证集有 376,599 个评分目标、1,148,007 字节；测试集有 428,405 个评分目标、1,292,013 字节。所有模型保持词表、数据与评分协议一致。

BPB 定义为 `Σ[-ln p(真实下一 token | 已观察前缀)] / [ln(2) × 原始 UTF-8 字节数]`，越低越好。它不是准确率，也不能与采用不同分词协议的困惑度直接比较。

基线为 4 层、宽度 128、4 头 GPT，共 1,088,256 个参数，采用学习式绝对位置编码、Pre-LayerNorm、因果注意力、GELU 前馈网络、残差连接和词嵌入权重共享。项目复用课程代码，研究的是已知方法在本任务中的效果，不声称提出新的算法。

## 2. 改进方法

**前馈输出 dropout。** 在原前馈网络输出后、残差相加前加入 dropout，初期测试 0.10 和 0.05。它旨在抑制特征过度依赖，但是否有收益由验证结果决定，不能仅因其常用而假定有效。

**SwiGLU。** 将原 `Linear → GELU → Linear` 替换为 `down(SiLU(gate(x)) × value(x))`，使用输入相关的乘法门控。中间宽度取 `round(8d/3)`，以控制三个线性映射带来的参数增长。宽度 128 下仅比基线增加 168 个参数，因此早期比较近似匹配参数量。

**训练预算及容量。** 分别考察 2400 与 6000 步、宽度 128 与 192、层数 4 与 6。相同训练目标数不等于相同计算量；同时，脚本的余弦学习率依赖总步数，改变步数也改变学习率轨迹。

**RoPE 组合。** 最新候选移除学习式绝对位置表，在各注意力头的 Q、K 上按位置旋转，V 保持不变，继续使用因果掩码。正余弦由窗口内位置计算，每个窗口从零开始。该实现使用 GELU，并在输入 embedding、注意力权重、注意力输出和前馈输出上加入 dropout。当前候选还把宽度提高到 256、dropout 提高到 0.10。因此这是 RoPE 与容量、正则化的组合实验，不是纯粹的 RoPE 消融。实现继承课程 GPT 的通用接口，并参考了提供的 RoPE 示例代码；复用来源应在 README 中一并说明。

## 3. 实验设置

所有正式运行使用 seed=17、batch size=32、context=256。1200、2400、6000 步分别处理 9,830,400、19,660,800、49,152,000 个训练目标，重复采样也计入成本。训练器从随机初始化训练，没有 checkpoint 续训路径。

训练使用 AdamW，最大学习率 0.001，weight decay 0.1，100 步预热与脚本中的余弦衰减，梯度裁剪阈值 1.0。旧实验使用 CPU FP32；RoPE 训练日志记录 NVIDIA A100-SXM4-40GB、BF16，验证函数使用 FP32，另外完成了 CPU FP32 复现。不同设备和可能不同并发负载下的训练时间不能作为架构加速证据。日志未完整记录每次历史 CPU 型号和并发情况。

训练器保存最后一步而非验证最佳权重。全部主要实验为单种子，不声称统计显著性。下表来自现存 metrics.json；精确运行路径、数据和哈希可见配套实验表与 evidence JSON。

## 5. 对照与消融分析

**早期结构对照（E1–E4）。** 相同 1200 步下，SwiGLU 相比 GELU 降低验证 BPB 0.06320；两种 dropout 比例单独加入基线时反而变差。说明短训练、小模型条件下，SwiGLU 有收益，而 dropout 未显示收益。固定种子并不保证各结构所有参数初始化完全一致。

**训练量与容量（E5–E8）。** 同一组合从 2400 到 6000 步，BPB 从 1.83138 降至 1.73074。随后相同 6000 步下增宽至 192，降至 1.66915；再增加到 6 层，降至 1.63767。后两组分别隔离了特定设置下的宽度和深度变化，但计算成本随之增加。

**六层消融（E8–E10）。** 去掉 SwiGLU、保留 GELU 和相同 dropout 后，BPB 从 1.63767 降至 1.60688，改善 0.03080；去掉 dropout、保留 SwiGLU 后，BPB 升至 1.66182，变差 0.02415。这说明 SwiGLU 并非在所有设置下更优，dropout 在这一 SwiGLU 设置中有帮助。该组相同训练量对照可作为关键机制的消融证据。纯 SwiGLU 在 5500 步达到 1.66141，但该步没有保存权重，不能把它当作现有 checkpoint 成绩。

**RoPE 组合（E11）。** CPU FP32 验证为 1.52769829，比 E10 的验证成绩更低，但它还改变宽度、dropout 的位置与比例、训练硬件和精度。缺少同宽度 256、同 dropout 设置、同训练条件下的绝对位置编码对照，因此不能隔离 RoPE 的独立贡献；现有 SwiGLU 消融也不能代替这一对照。若报告将 RoPE 作为唯一关键机制，这仍是待补的实验缺口。

## 8. 结论与个人工作、AI 使用说明

本项目最重要的发现是改进效果依赖模型规模和训练设置：小模型的 SwiGLU 收益没有在较大模型中保持，dropout 的效果也随设置变化。容量扩展与更长训练改善了验证表现，但增加成本；RoPE 组合获得当前最低验证分数及 1.54400 的完整测试 BPB，其独立机制收益尚未分离。后续工作应优先补同条件 RoPE 消融、多种子稳定性及完整测试资源验证，而不是仅增加结构复杂度。

**个人工作。** 我阅读并逐步理解了课程 GPT 的模型和训练流程，在 AI 建议的基础上编辑 student.py 和配置文件，执行多轮训练，核对日志并比较不同设置。我主动提出增加 block 数量，讨论在继承 GPT 的基础上接入 RoPE，并根据实验需要补充 GELU、SwiGLU 与 dropout 对照。项目中的方案由我逐步选择和实施，而不是直接采用一份现成结果。对实验结论，我需要依据实际指标作判断，包括接受 GELU 在较大设置下优于 SwiGLU 的结果，并区分验证成绩、测试成绩和资源成本。
